# Nimura: 瞬き検出×姿勢推定による健康推進Androidアプリ 設計書

## 概要

スマートフォンのインカメラを用いて瞬き頻度と姿勢を計測し、複合疲労スコアを算出。ナッジ理論に基づく介入（リマインド通知）により、ユーザーの健康行動変容を促すAndroidアプリ。

修士論文のシステムとして開発し、**ユーザビリティと行動変容効果**をRCTで評価する。

## 研究の背景と新規性

### 先行研究

- **瞬き×疲労**: 瞬き頻度は疲労の指標として広く確立。画面使用時に約66%減少する（Cognitive demand, digital screens and blink rate, 2015）
- **EAR (Eye Aspect Ratio)**: 閉眼検出の標準指標。閾値 < 0.2 が一般的（Soukupová & Čech, 2016）
- **PERCLOS**: FHWA/NHTSAが眠気検出の生理指標として検証。≥ 0.3 で眠気状態（Wierwille, 1994; FHWA-MCRT-98-006）
- **瞬き+姿勢の融合**: パナソニック技報（2021）で、瞬き情報に姿勢情報を融合しドライバー眠気推定のF1スコアが0.358→0.523に向上

### 本研究の新規性

1. **瞬き×姿勢の複合指標をスマホ単体で実現** — 先行研究は専用デバイス・車載カメラが中心
2. **バックグラウンド計測**による自然な使用環境下でのデータ取得
3. **ナッジ理論に基づく介入**と行動変容効果のRCTによる検証
4. 技術（ML推定）とHCI（行動変容）の**学際的アプローチ**

## 技術スタック

| 項目 | 技術 | 選定理由 |
|---|---|---|
| 言語 / UI | Java + XML Layout | 情報豊富、安定、MediaPipe/MPAndroidChartとの相性良好 |
| ML ライブラリ | MediaPipe (Google) | Face Mesh + Pose が1ライブラリ。オンデバイス処理、Apache 2.0 |
| ローカルDB | Room (SQLite) | 疲労スコア・セッション・介入ログの保存 |
| グラフ描画 | MPAndroidChart | Java ネイティブのOSSチャートライブラリ |
| カメラ | CameraX | Foreground Service でのバックグラウンド動作に対応 |

## アーキテクチャ

5層構成:

```
入力層: スマホ内蔵インカメラ
    ↓
検出層: MediaPipe Face Mesh (468点) + Pose (33点)
    ↓
分析層: 疲労スコアエンジン（複合疲労スコア 0-100）
    ↓
介入層: ナッジ介入エンジン（段階別通知）
    ↓
記録層: Room DB + トレンド可視化（MPAndroidChart）
```

## 画面構成とユーザーフロー

### 画面一覧

| 画面 | 役割 |
|---|---|
| ホーム | 前回の疲労スコア表示、瞬き頻度・姿勢スコアのサマリー、「計測を始める」ボタン |
| バックグラウンド計測中 | 常駐通知（「計測中」）のみ。ユーザーは他アプリを自由に使用 |
| 結果 | 疲労スコア + ナッジ介入（改善提案）。通知タップで表示 |
| 履歴 | 日/週/月のトレンドグラフ |
| 設定 | 通知設定・閾値・プロフィール |

### 基本フロー

1. アプリを開く → ホーム画面で前回のスコアを確認
2. 「計測を始める」をタップ → カメラがバックグラウンドで起動
3. **ユーザーは他のアプリ（YouTube、SNSなど）を自由に使用**
4. 裏で瞬き+姿勢を継続的に記録（Foreground Service + CameraX）
5. 疲労スコアが閾値を超えたらプッシュ通知でリマインド
6. 通知タップで結果画面 → 疲労スコア + ナッジ（改善提案）表示
7. ナッジに従って行動（ストレッチ、休憩など）、または「あとで」で閉じる
8. 履歴画面でトレンドを確認

### バックグラウンド動作の技術要件

- **Foreground Service** + **CameraX** でバックグラウンドカメラ動作
- 常駐通知を表示（「Nimura - 計測中」） — Androidの要件を満たす
- ステータスバーに緑のカメラインジケータ表示（Android 12以降のOS仕様、許容する）
- 疲労スコアが閾値を超えたらプッシュ通知で介入
- 計測の停止: ユーザーが常駐通知の「停止」ボタンをタップ、またはアプリを再度開いて「計測を止める」をタップ。バッテリー残量が15%以下になった場合は自動停止

## 疲労スコア算出ロジック

### 先行研究に基づく指標（確立された値をそのまま採用）

| 指標 | 算出方法 | 閾値 | 出典 |
|---|---|---|---|
| 瞬き頻度 | 1分あたりの瞬き回数カウント | 正常: 15-20回/分、疲労: <10回/分 | Cleveland Clinic; Cognitive demand & digital screens (2015) |
| EAR (Eye Aspect Ratio) | Face Meshの目周辺ランドマークから目の縦幅/横幅を算出 | 閉眼判定: EAR < 0.2 | Soukupová & Čech (2016) |
| PERCLOS | 一定時間内に目が80%以上閉じている時間の割合 | 眠気判定: ≥ 0.3 | Wierwille (1994); FHWA-MCRT-98-006 |

### 予備実験で決定する項目

| 項目 | 仮の初期値 | 決定方法 |
|---|---|---|
| 頭部前傾の疲労判定角度 | CVA < 48度 (FHP臨床定義参考) | 被験者5-10名で正常/疲労時の角度差を計測 |
| 肩傾きの疲労判定角度 | 左右差 > 10度 | 同上の予備実験で同時取得 |
| 複合スコアの重み (α, β) | α=0.5, β=0.5 | 主観疲労度(VAS)と各指標の相関分析で決定 |
| ナッジ通知のスコア閾値 | 軽度:31 / 中度:61 / 重度:81 | 疲労段階とスコア分布を照合して調整 |

### スコア算出フロー

```
Step 1: 生データ取得
  Face Mesh → EAR値 (毎フレーム)
  Pose → 肩・鼻の座標 (毎フレーム)

Step 2: 指標算出
  瞬き頻度 = 瞬き回数 / 経過分
  PERCLOS = 閉眼フレーム数 / 全フレーム数
  頭部角度 = arctan(鼻-肩の座標差)
  肩傾き = |左肩Y - 右肩Y|

Step 3: 正規化 (0-100)
  目の疲労 = f(瞬き頻度, PERCLOS)
  姿勢疲労 = g(頭部角度, 肩傾き)
  ※ f, g のマッピング関数は予備実験で決定

Step 4: 複合スコア算出
  S = α × 目の疲労 + β × 姿勢疲労
  ※ α, β は予備実験で決定（初期値: 各0.5）

Step 5: 介入判定
  閾値超過 → 段階に応じた通知を発行
```

### ナッジ介入の段階

| スコア | 段階 | 介入内容 |
|---|---|---|
| 0-30 | 良好 | 介入なし（記録のみ） |
| 31-60 | 軽度疲労 | 穏やかな通知（「少し目を休めましょう」） |
| 61-80 | 中度疲労 | 具体的なアクション提案（20-20-20ルール、ストレッチ） |
| 81-100 | 重度疲労 | 強い休憩推奨 + 休憩タイマー提示 |

### サンプリング戦略（バッテリー配慮）

- **30秒ごとに3秒間のサンプリング** — 3秒間カメラフレームをML解析
- 直近5回分のサンプル（約2.5分間）の移動平均で疲労スコアを算出
- スコアが閾値を超えたら通知、超えなければ次のサンプリングまで待機
- カメラは常時ONだが、ML推論は間欠的にすることでCPU/バッテリーを節約

## 評価実験の設計

### 実験構成

| Phase | 期間 | 内容 |
|---|---|---|
| Phase 0: 予備実験 | 約1週間 | 5-10名で姿勢指標の閾値・複合スコアの重み・ナッジ閾値を決定 |
| Phase 1: ベースライン | 1週間 | 全被験者がアプリ（計測のみ、通知なし）を使用。事前アンケート実施 |
| Phase 2: 介入期 | 2週間 | 介入群: ナッジ通知あり / 対照群: 記録のみ |
| Phase 3: 事後評価 | 1-2日 | アンケート（SUS + 健康意識） + データ分析 |

### 群間比較デザイン（RCT）

**介入群 (n=15-20):**
- バックグラウンドで瞬き+姿勢を計測
- 疲労スコアをリアルタイム算出
- **ナッジ通知あり**（休憩・ストレッチ提案）
- 履歴・トレンド表示あり
- ナッジへの応答をログ記録

**対照群 (n=15-20):**
- バックグラウンドで瞬き+姿勢を計測
- 疲労スコアをリアルタイム算出
- **ナッジ通知なし**（データ記録のみ）
- 履歴・トレンド表示なし
- 介入なしの自然な行動を記録

被験者はランダムに割り付け。対照群には「計測のみ」のアプリと説明し、ナッジ機能の存在を伝えない。

### 予備実験

| 項目 | 内容 |
|---|---|
| 目的 | 姿勢指標の閾値、複合スコアの重み、ナッジ閾値を決定 |
| 被験者 | 5-10名（本実験とは別の参加者） |
| 手順 | 1. スマホで30分間の作業タスク（動画視聴・SNS閲覧等） |
| | 2. 5分ごとにVAS（主観疲労度）を記録 |
| | 3. 同時にアプリで瞬き・姿勢データを取得 |
| | 4. 主観疲労度と各指標の相関分析 → 閾値・重みを決定 |
| 論文での記述 | 「予備実験により閾値を決定した」として方法論に記載 |

### 評価指標（3軸）

**1. 行動変容の客観データ:**
- ナッジ応答率（通知に対して「実行する」を選んだ割合）
- 疲労スコアの推移（Phase 1 vs Phase 2 の比較）
- 休憩行動の頻度（ナッジ後にスマホ使用を中断した回数・時間）

**2. 主観評価アンケート:**
- SUS (System Usability Scale) — ユーザビリティの標準尺度（10項目）
- 健康意識の変化 — 独自質問紙: 姿勢・目の疲れへの意識（リッカート5段階）
- ナッジの有用性 — 介入群のみ: 通知の適切さ・頻度・内容への満足度

**3. 群間比較の統計分析:**
- 疲労スコア変化: 介入群 vs 対照群（対応のないt検定 or Mann-Whitney U検定）
- 健康意識スコア: Phase 1 → Phase 2 の変化を群間比較

## データモデル（Room DB）

### 主要テーブル

```
sessions テーブル:
  - id (PK)
  - start_time (TIMESTAMP)
  - end_time (TIMESTAMP)
  - is_active (BOOLEAN)

measurements テーブル:
  - id (PK)
  - session_id (FK → sessions)
  - timestamp (TIMESTAMP)
  - blink_rate (FLOAT) -- 瞬き頻度 (回/分)
  - ear_value (FLOAT) -- EAR値
  - perclos (FLOAT) -- PERCLOS値
  - head_tilt_angle (FLOAT) -- 頭部前傾角度 (度)
  - shoulder_tilt_angle (FLOAT) -- 肩傾き角度 (度)
  - eye_fatigue_score (INT) -- 目の疲労スコア (0-100)
  - posture_fatigue_score (INT) -- 姿勢疲労スコア (0-100)
  - composite_fatigue_score (INT) -- 複合疲労スコア (0-100)

nudge_logs テーブル:
  - id (PK)
  - measurement_id (FK → measurements)
  - timestamp (TIMESTAMP)
  - nudge_level (ENUM: mild, moderate, severe)
  - nudge_content (TEXT) -- 表示したナッジの内容
  - user_response (ENUM: accepted, dismissed, ignored)
  - response_time_ms (INT) -- 応答までの時間

daily_summaries テーブル:
  - id (PK)
  - date (DATE)
  - avg_fatigue_score (FLOAT)
  - avg_blink_rate (FLOAT)
  - avg_posture_score (FLOAT)
  - total_nudges (INT)
  - nudge_accept_rate (FLOAT)
  - total_measurement_minutes (INT)
```

## ターゲット環境

- Android 8.0 (API 26) 以上
- インカメラ搭載端末
- サーバー不要（全処理オンデバイス）
